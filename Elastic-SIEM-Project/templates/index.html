SIEM-IA · Panel de supervisión

Cómo funciona este panel cargando…

Arquitectura de detección → análisis → acción

Agente 1 (determinístico): classifier.py agrupa eventos crudos por IP/host y aplica reglas fijas de umbral (ej. 20+ fallos de auth = fuerza bruta). Rápido, barato y 100% auditable — nunca usa IA para esta parte, así el resultado siempre es reproducible.

Agente 2 (IA con fallback): siem_agent.py traduce la clasificación a una explicación en lenguaje claro (Gemini si hay API key configurada; si no, un análisis determinístico de respaldo — nunca deja al analista sin explicación).

Cómo el Agente 2 razona mejor sin decidir más

Tres capacidades que amplían el análisis, no la autonomía del sistema:

  • Correlación entre incidentes — si varios incidentes activos comparten una IP (banner morado ), se marcan como una misma campaña en vez de leerse como eventos sueltos.
  • Contexto histórico — antes de analizar, revisa decisions.jsonl buscando decisiones previas sobre esa IP en otros incidentes ("¿ya la bloqueamos antes?").
  • Explicabilidad — la severidad y la probabilidad de falso positivo no son una caja negra: cada incidente muestra los factores concretos (umbral superado, confirmación del SIEM, etc.) que llevaron a esa conclusión.

Los tres se calculan siempre en Python (no los redacta el LLM) por el mismo motivo que los comandos: son hechos auditables, no una interpretación que pueda variar entre corridas.

Por qué los comandos no los genera la IA

Los comandos sugeridos salen siempre del playbook fijo del Agente 1, nunca del LLM. El campo message de un log SSH lo puede escribir un atacante (ej. el nombre de usuario que tipea); si un LLM generara comandos a partir de eso, una inyección de prompt en el log podría terminar sugiriéndole un comando malicioso al operador. Con comandos fijos, esa superficie de ataque no existe.

El principio rector

La IA sugiere, el humano decide. El sistema nunca ejecuta una acción de contención por su cuenta. Cada click en Aprobar/Descartar queda en decisions.jsonl, un log append-only e inmutable — trazabilidad completa de quién decidió qué y cuándo, la base de cualquier auditoría de este flujo.
